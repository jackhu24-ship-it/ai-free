## 一、 系統分層架構 (Dual-Loop Architecture)

系統在硬體與通訊層面切分為「快環」與「慢環」，透過無鎖共享記憶體與硬體中斷進行解耦與安全仲裁：

```
                 [ 感測輸入 / 視覺 + 點雲 + 遙測 ]
                                │
           ┌────────────────────┴────────────────────┐
           ▼                                         ▼
┌──────────────────────────────┐          ┌──────────────────────────────┐
│  慢環：神經意圖層 (Cognitive) │          │  快環：符號防禦層 (Safety)   │
│  (10–50 Hz / Linux RT / NPU) │          │  (500–1000 Hz / 硬實時 RTOS) │
│  - 視覺語言動作模型 (VLA)    │          │  - 運動學/動力學投影         │
│  - 期望路徑與力矩預測        │          │  - 控制屏障函數 (CBF)        │
└──────────────┬───────────────┘          │  - 確定性安全狀態機          │
               │ 候選動作指令             └──────────────┬───────────────┘
               │ (Candidate Action)                      │ 狀態反饋 (1kHz)
               ▼                                         ▼
   ┌───────────────────────────────────────────────────────────┐
   │             形式化安全仲裁器 (Safety Arbiter)              │
   │  - 二次規劃投影 (QP Projection / WCET <= 200us)           │
   │  - 物理邊界過濾 (Torque / Velocity / Friction Limit)      │
   │  - 越界硬切換至降級策略 (Safe Fallback Damping Brake)     │
   └─────────────────────────────┬─────────────────────────────┘
                                 ▼ 最終安全驅動指令 (1kHz)
                     [ 馬達驅動器 / CAN-FD / EtherCAT ]
```

### 1. 慢環（Cognitive Loop，10–50 Hz）
- **運行環境**：Host / NPU（Linux PREEMPT_RT 環境）。
- **職責**：負責高層多模態感知與行為意圖規劃，輸出「候選軌跡向量」與「建議力矩矩陣」。
- **容錯特性**：允許小幅延遲與網路抖動，**絕對不直接掛載底層執行器驅動**。

### 2. 快環（Deterministic Loop，500–1000 Hz）
- **運行環境**：專屬硬實時核心（RTOS 或 Bare-metal Cortex-R/M / RISC-V）。
- **職責**：運行控制屏障函數（Control Barrier Functions, CBF）與接觸力學約束矩陣。
- **時序保證**：每次取樣只做確定性矩陣乘加運算，**執行週期嚴格小於 1 毫秒（$\le 1\text{ ms}$）**。

### 3. 形式化安全仲裁器（Safety Arbiter）
- **雙環守門人**：慢環傳來的候選指令必須在微秒級通過二元二次規劃（QP）求解或多邊形邊界投影：
  $$\min_{u} \frac{1}{2} \|u - u_{\text{slow}}\|^2 \quad \text{s.t.} \quad u_{\text{lower}}(x) \le u \le u_{\text{upper}}(x)$$
- **前向不變集判定**：若解空間落在安全集合（Forward Invariant Set $\mathcal{C}$）內則透傳；一旦偵測到邊界越界、失步或慢環心跳逾時（$>35\text{ ms}$），**零延遲攔截並由符號狀態機接管**，強制切換至阻尼制動（Damping Brake: $\tau = -D \dot{q}$）或安全回正姿態。

## 二、 核心驗證指標（KPIs & Safety Gates）

驗證不看傳統 AI 的「平均勝率」，而是死盯「最壞情況延遲（WCET）」與「邊界穿越次數」：

| 維度 | 指標名稱 | 目標值 (KPI Target) | 驗證手段 |
| :--- | :--- | :--- | :--- |
| **實時性** | 快環最大抖動 (Jitter) | $\le 50\,\mu\text{s}$ | 硬體示波器監控 GPIO 翻轉與 RTOS 延遲測試 |
| **安全性** | 物理約束違背率 (Invariant Violation) | **嚴格為 0 (Zero-Violation)** | 注入不可行的高層噪聲指令，確認 100% 被仲裁器攔截 |
| **仲裁延遲** | 符號屏障過濾與 QP 求解耗時 | $\le 200\,\mu\text{s}$ | 嵌入式端純整數/單精度浮點運算靜態 WCET 分析 |
| **邊界接管** | 異常工況切換至 Safe Fallback 響應時間 | $\le 1\,\text{ms}$（單週期內） | 模擬慢環進程崩潰（SIGKILL）與通訊封包斷裂測試 |
| **動態泛化** | 域隨機化抗擾能力 (Domain Randomization) | 負載 $\pm 30\%$ 突變不失穩 | MuJoCo / 實物衝擊測試與動力學參數擾動 |

## 三、 第一期 POC 8 週落地路線圖 (6–8 Weeks Roadmap)

聚焦在「高動態機械臂 / 特種四足末端力控」場景，在純虛擬環境打通閉環後無縫移植到硬體驗證台：

### 第 1–2 週：物理約束形式化定義與雙環通訊原型
- 在 MuJoCo 中建立多自由度動力學基準模型，推導其關節極限、速度包絡線與接觸力矩限制條件。
- 撰寫 Rust 基礎運行時，建立基於 POSIX 共享記憶體（或輕量級 Zenoh）的快慢環無鎖隊列（RingBuffer），驗證慢環（30Hz 模擬神經網路）與快環（1000Hz 符號守衛）的通訊延遲。

### 第 3–4 週：CBF 仲裁器演算法實現與極端故障注入
- 在快環中實作輕量化控制屏障函數（CBF），針對關節過速、末端超範圍、地面碰撞等物理邊界建立數學約束。
- **主動破壞測試**：人為在慢環隨機注入畸變軌跡、高頻雜訊或延遲高達 500ms 的「有毒動作指令」，驗證符號仲裁器能否在 1 個週期內切換至被動合規（Compliance）狀態，確保實體模型絕不撞機。

### 第 5–6 週：端側 NPU 模型編譯與物理硬體台架實裝
- 將輕量化動作生成模型（如小型擴散策略模型 Diffusion Policy 或 Actor-Critic 模型）量化並編譯部署至邊緣加速單元。
- 快環代碼交叉編譯至即時嵌入式板卡，透過 CAN-FD / EtherCAT 直連執行器電機驅動。

### 第 7–8 週：封閉場景全流程驗證與 GSN 安全論證交付
- 實機執行「盲抓 / 動態抗推 / 突發斷訊」三類物理壓力測試。
- 輸出第一份基於 GSN（Goal Structuring Notation）的架構安全論證報告，證明系統在任意軟體故障下均能維持物理確定性安全，完成第一期交付閉環。
